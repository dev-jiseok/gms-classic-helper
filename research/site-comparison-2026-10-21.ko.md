# GMS 클래식 개인 도우미 사이트 비교와 개발 제안

확인일은 2026년 10월 21일이며, 대상은 사용자가 제공한 8개 사이트입니다. 글클메 지지를 사용성의 주요 참고 대상으로 삼고, 공략·드롭·맵·시세를 내 캐릭터의 다음 행동으로 연결하는 개인 도우미를 제안합니다.

기존 서비스에는 도감, 돈퀘스트, 사냥터 계산, 장비 최적화, 특가 탐색이 이미 있습니다. 개발 가치는 이 기능들을 한 캐릭터 상태로 연결하고, 현재 가격과 실제 사냥 기록을 반영해 선택의 이유와 순서를 알려주는 데 있습니다. 관찰한 화면만으로 해당 조합이 모든 경쟁 서비스에 없다고 단정하지는 않습니다.

## 확인 범위

REA 6.7.0의 브라우저 시나리오로 화면, 접근성 구조, 선언한 입력과 클릭 결과, 네트워크 응답 상태를 관찰했습니다. 검색 도구로 접근 가능한 원문도 대조했습니다. 로그인하지 않은 공개 화면을 중심으로 확인했으며, 서버 코드·내부 DB·전체 페이지의 모든 분기를 복원한 결과는 아닙니다.

글클메 지지와 GMS 클래식 허브는 처음의 headless 세션에서 접근이 제한됐으나, 화면이 보이는 일반 Chrome 실행으로 정상 페이지를 확인했습니다. 사용자 Chrome의 기존 프로필이나 로그인 정보를 가져오지 않았습니다.

클래식마켓의 인증된 시세와 글클메 지지의 부엉이는 로그인·인증 이후의 결과를 검증하지 않았습니다. 메이플 마켓은 필터와 특가·알림 설명을 확인했으나, 매물 결과는 관찰 세션에서 로딩이 끝나지 않았습니다. 고확 사이트는 화면은 열렸지만 데이터 요청이 HTTP 402로 실패했습니다.

## 제안하는 핵심 기능

### 내 상황에서 지금 할 일

첫 화면은 직업, 레벨, 현재 위치, 장비·주요 스킬, 예산, 완료 퀘스트, 보유 재료, 오늘 플레이 시간과 목표를 받습니다. 처음에는 직업·레벨·목표만으로 시작하고, 상세 입력이 들어오면 추천을 정밀하게 만듭니다.

추천은 다음 행동, 이유, 적용 조건, 예상 비용과 시간, 다음 단계까지 연결합니다. 예를 들어 특정 장비를 먼저 구하면 주력 몬스터의 처치 횟수가 줄어드는지, 선행 퀘스트를 먼저 끝내면 같은 동선에서 재료 수집을 겸할 수 있는지 설명합니다. 이 문서의 예는 제품 동작 제안이며 특정 직업에 대한 확정 공략이 아닙니다.

공략 규칙에는 직업·레벨·스킬·장비 조건, 필요한 선행, 현재 패치, 근거 링크와 예외를 저장합니다. 예외가 있는 추천에는 ‘무조건 필수’ 대신 언제 유리한지를 보여줍니다. 시기 제한 보상과 되돌리기 어려운 선택은 먼저 표시합니다.

하나의 총점만 보여주기보다 경험치 우선·메소 우선·균형·편한 사냥을 나누고 상위 후보의 차이를 설명합니다. 개인 실측이 쌓이면 예상 처치량을 보정합니다.

확인한 [NiaDB의 몬스터 상세](https://meowdb.com/msclassic/ko/monsters/13)는 실제 목격 드롭과 옛 버전 참고표, OSMLib 참고 확률을 구분합니다. 참고 확률은 현재 Classic World의 실측 확률로 보장되지 않습니다. 확률이 없는 아이템은 숫자를 만들어 시간당 메소에 합산하지 않고, 고가 드롭 후보와 불확실성을 따로 보여줘야 합니다.

드롭 확률을 사용할 수 있을 때의 기본 모델은 다음과 같습니다. 실제 플레이에서는 변동 폭과 미판매 재고를 함께 표시합니다.

- 시간당 EXP = 시간당 처치량 × 실제 적용되는 몬스터별 EXP
- 시간당 전리품 기대가치 = 몬스터별 처치량 × 아이템별 드롭 확률 × 현실적인 순판매가의 합
- 순수익 = 획득 메소 + 전리품 가치 − 소모품·이동·거래 비용

### 돈퀘스트와 육성 동선

고정 메소와 보상 아이템의 가치를 더하고, 재료를 팔았을 때의 기회비용·구매비·이동·소모품 비용을 뺍니다. 직접 모은 재료도 시장 가치가 있으면 비용에 반영합니다. 랜덤 보상은 선택 보상과 구분하고 확률이 확인될 때 기대값을 계산합니다.

완료한 선행, 이미 모은 재료, 같은 지역의 퀘스트를 묶어 ‘지금 끝내기 좋은 순서’를 만듭니다. 사냥으로 얻는 경험치·재료를 퀘스트 가치와 중복 계산하지 않도록 합니다. 예상 시간을 모르면 실제 수익률처럼 단정하지 않고 완료 조건과 비용 중심으로 안내합니다.

### 예산 안에서 장비를 바꾸는 순서

동일 아이템 이름만으로 최저가를 고르지 않습니다. 공격력·주스탯·보조스탯·명중·공속·잔여 업횟수·거래 상태를 구분하고, 착용 조건을 전체 세트 기준으로 확인합니다.

현재 장비에서 한 슬롯을 바꿨을 때 DPS, 처치 횟수, 안정적인 한 방 확률과 사냥터 선택지가 얼마나 바뀌는지를 가격과 비교합니다. 값이 싼 장비와 메소당 효과가 큰 장비를 구분합니다. 구매·제작·퀘스트 획득을 비교하고, 관찰한 매물의 출처와 마지막 확인 시간을 보여줍니다. 관찰 범위 밖까지 포함한 ‘전체 서버 최저가’는 보장하지 않습니다.

### 이벤트와 놓치면 손해인 행동

이벤트의 적용 월드·시작과 종료·참여 조건·일일 또는 주간 초기화·수령 마감을 관리합니다. 한국 시간과 서버 시간을 함께 보여주고 공식 공지를 근거로 유지합니다. 뉴스 게시일을 이벤트 종료일로 쓰지 않습니다.

개인 상태에 맞춰 오늘 참여 가능한 것, 먼저 해금해야 하는 것, 마감이 가까운 보상만 우선 노출합니다. 이번에 확인한 사이트의 뉴스·일정 기능과 구분되는 개인화 방향입니다.

### 동일한 정보를 연결하는 기준

자료마다 별칭, 자체 숫자 ID, 게임 아이템 ID와 이름이 다릅니다. 예를 들어 장갑 공격력 주문서의 관련 화면은 NiaDB의 item-db/114와 클래식마켓의 item/2040801에 각각 있습니다. 따라서 사이트 ID를 게임의 공통 ID로 간주하면 안 됩니다.

게임 빌드·월드·지역·시점별로 아이템·몬스터·퀘스트를 식별하고, 원자료의 ID와 출처를 별도로 연결해야 합니다. 옛 메이플·MapleSEA·GMS 83의 이미지나 참고 데이터가 현재 MCW의 수치와 같다고 가정하지 않습니다. 해금되지 않은 지역과 예고된 스킬은 추천 대상에서 구분합니다.

### 가격의 품질

가격에는 매수 호가, 매도 호가, 실제 판매로 표시된 관찰, 거래 완료 게시물, NPC 가격이라는 종류를 보존합니다. 단가와 묶음 가격, 옵션, 수량, 관찰 시간, 표본 수와 원본 출처도 보관해야 합니다.

중복 광고·오독·오래된 게시물·특이 옵션을 구분하고, 동일 자료가 여러 사이트에 재노출된 경우 독립된 거래 표본으로 중복 계산하지 않습니다. 이 조건이 충족돼야 ‘시세 기반 추천’의 품질을 평가할 수 있습니다.

### 데이터 확보와 재사용

[NiaDB의 재사용 안내](https://meowdb.com/reuse)는 출처를 붙인 일부 사실·인용과 전체 DB·페이지 복제를 구분합니다. [메소워치의 약관](https://meso.watch/terms)은 가격 자료의 자동 수집과 재사용을 제한합니다. 글클메 지지와 GMS 클래식 허브도 자체 자료의 복제·자동 수집 제한을 표시합니다.

따라서 분석한 화면과 기능 흐름을 참고해 구현하되, 기존 서비스의 코드·글·DB를 통째로 가져오는 것을 전제로 설계하면 안 됩니다. 연동을 허용한 공급원, 적합한 조건의 원자료, 개인이 입력하거나 직접 기록한 자료를 구분하고 데이터 사용 조건을 먼저 확정해야 합니다. 이번 조사에서는 운영자에게 연락하거나 허가를 요청하지 않았습니다.

[ClassicRank 개발자 문서](https://classicrank.com/developer)는 키 없는 읽기 API와 별도 읽기 키를 안내합니다. 공개 자료만으로 구현 가능한 연동 후보이며, 장비·스킬까지 자동으로 불러오는 근거는 아닙니다.
